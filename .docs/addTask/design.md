# 日常任务登记 — 技术设计

## 概述

基于现有的"运维工时补录"(`issueLinkPush.opsWorkHourRecord`) 命令，新增"日常任务登记"(`issueLinkPush.dailyTask`) 命令。两者逻辑相似：选择项目/产品/区域/实施项目 → 填写工时信息 → 填写任务模板内容 → 创建 DevOps Task → 登记工时。但日常任务不依赖本地 Git 仓库（不需要 commit/push）。

## 核心差异

| 维度 | 运维工时补录 | 日常任务登记 |
|---|---|---|
| Git 依赖 | 需要 git repo + staged changes + commit + push | **无 Git 依赖** |
| 项目/产品记忆 | 基于 git origin URL | **基于工作区路径** |
| commit type 选择 | 有（upd/feat/fix...） | **无** |
| 任务类型 | 固定 `taskWorkItemCatalog='3'` | **由工时类型自动映射** |
| importance | `'2'`（中等）[旧值] | `'1'`（一般）[对齐 Web UI] |
| priority | `'2'`（高） | `'2'`（高）|

## 交互流程

```
Step 1: 输入任务标题
Step 2: 选择研发项目 → 级联产品        ← 工作区路径记忆
Step 3: 产品版本（自动or手动）
Step 4: 区域（标题自动匹配 or 手动选择）
Step 5: 实施项目（级联区域）
Step 6: 选择工时类型 → 自动映射任务类型  ← 核心新增逻辑
Step 7: 投入工时
Step 8: 完成度 + 预计结束时间（<100%时）
Step 9: 任务模板内容（复用 TaskTemplateFlow）
Step 10: 确认页 → 创建 DevOps Task → 登记工时
```

## 涉及的文件

### 新增文件
- `src/vscode/DailyTaskFlow.ts` — 日常任务交互流程
- `src/vscode/WorkspaceMapping.ts` — 基于工作区路径的项目/产品记忆

### 修改文件
- `src/core/DevOpsProvider.ts` — `CreateTaskInput` 新增 `taskWorkItemCatalog?` 字段
- `src/core/providers/CompanyDevOpsAdapter.ts` — `createTask()` 使用 `input.taskWorkItemCatalog ?? '3'`
- `src/vscode/QuickPickFlow.ts` — `collectOpsWorkHourRecord` 对齐 Web UI 默认值（importance: '1'）
- `src/extension.ts` — 注册新命令 + `runDailyTask` 函数

## Web UI 默认值（来源：HAR 录制）

```
importance:      '1'  →  1=一般, 2=中等, 3=重要, 4=关键
priority:        '2'  →  1=紧急, 2=高, 3=中, 4=低
workSource:      '3'  →  （字典值，Web UI 默认）
taskWorkItemCatalog: 动态映射（无匹配时 fallback '3'）
```
